Random-walk pipeline map

What changes when the pipeline runs with --mode walk: how the absorbing random walk in metaboenrich/walk.py works, step by step, which function does each part, and which package does the work underneath. Every function and package call named here was checked against the code at commit 0f6c135 (branch directed-rw).

In one paragraph. --mode walk keeps steps 1–4 of the main run and swaps step 5. Instead of solving Kirchhoff's equations on the undirected graph, it releases walkers at the increased metabolites (sources), in proportion to |log2FC|, and lets them step only along reaction directions until a decreased metabolite (target) absorbs them. Walkers that hit a dead end are lost, and only walks that reach a target are scored. The maths is one sparse LU of (I − Q) on the walk's state space (scipy.sparse.linalg.splu, about 0.3 s on Human-GEM). That one factorisation gives every source's chance of reaching a target and its expected traffic over every arc. The walk returns the same FlowResult as current flow, so scoring and outputs are shared. The result tables gain one column, net_forward, and summary.json gains a few walk_* fields.

Not a random walk with restart (RWR). Walkers never teleport back to where they started. They stop when a target absorbs them or when they reach a dead end. The scores are expected traffic of successful walks, not a stationary distribution.

The walk's state space

The walk does not run directly on the metabolite–reaction graph. It runs on a larger directed graph of states built from it (step 5a), so that a walker always knows which way it is going through a reaction. The example below has two reactions: r1, A + B ⇌ C (reversible), and r2, C → D (irreversible). A is a source and D a target.

Walk run, step by step

Entry point: python -m metaboenrich --mode walk …, i.e. metaboenrich/__main__.py → main(). When args.mode == "walk" it calls absorbing_walk where it would otherwise call current_flow. Everything before and after that call is the same code as the default run.

1–4

Model, currency, DAA, graph: unchanged

gem.py · network.py · daa.py

The walk uses the same locked network as current flow (3,958 metabolites, 6,377 reactions, 16,356 edges); see pipeline.html, steps 1–4. It relies on three things those steps already produce:

  • Reaction.forward / Reaction.backward (step 1)Directions from the flux bounds: forward = ub > 0, backward = lb < 0. Reversible reactions have both.
  • Graph.arcs and Graph.edge_side (step 4)The directed arcs and whether each edge joins a substrate or a product. Step 5a reads these to decide which directions each reaction allows.
  • daa.phi (step 3)φ = |log2FC| per mapped metabolite. In walk mode main() always builds the {node: φ} map, whatever --pair-weight says.
5

Run the absorbing walk

metaboenrich/walk.py → absorbing_walk(graph, sources, targets, phi, kappa, tau, ground)

Releases walkers at the sources, follows reaction directions until a target absorbs them, and turns the expected traffic of the successful walks into the same per-node and per-edge arrays that current flow produces. The five parts below run in order inside one call.

5b  at = 1  or  1 − e−κφt  ·  Quv = (1 − au) / outdeg(u)
5c  (I − Q) h = a  →  h(u) = P(walk from u is absorbed)  ·  ws ∝ φs h(s)
5d  ns = (I − Q)−T es  →  traffic(u→v | success) = ns(u) Quv h(v) / h(s)
5e  net = M · traffic  →  throughput = ½ |B|ᵀ |net|  (− ½ absorbed at a target)  →  conductivity = Σs ws Ts
InGraph, source and target node lists, φ, optional κ, τ, groundOutFlowResult with net_forward and walk_info set
5a

Build the state space

walk.walk_states(graph) → WalkStates

States 0 … graph.n − 1 are the graph's own nodes. A metabolite's state is where walkers start, and a reaction's state is its first allowed direction. Each reversible reaction then gets a second state for its other direction, and every (reaction direction → product metabolite) step gets its own arrival state, so a walker on a metabolite remembers which direction it came from. Arcs run start → direction, direction → arrival, and arrival → any direction the metabolite feeds, except the opposite of the one just used. See the diagram above.

Functions and fields
  • walk_states(graph)Reads graph.arcs against graph.edge_side to set fwd[r] / bwd[r], then builds the inputs (metabolite → directions it feeds) and outputs (direction → products) maps and the arc list.
  • WalkStatesnode (graph node of each state), arrival mask, arcs arc_u → arc_v, the graph edge each arc runs along (arc_edge), and arc_sign (+1 metabolite → reaction, −1 reaction → metabolite).
  • oppositeMaps r→ to r← and back; the no-reversal rule skips that one arc.
Packages
  • dict · set · dataclassesDirection flags, input/output maps, the WalkStates container.
  • numpyFinal int64 arc arrays and the arrival mask.
Size21,787 states on Human-GEM (D17)
5b

Set absorption, prune dead states

walk.absorbing_walk · walk._can_reach

Only arrival states of targets absorb: a walker has to get there through a reaction. With full absorption (default) at = 1. With --walk-kappa κ, at = 1 − exp(−κ φt): a deep drop catches nearly every walker, a mild one lets some walk on to targets further along. A reverse breadth-first search from the absorbing states marks every state that can still reach one (live). Transition probabilities use the full out-degree, so a step into a dead state is lost mass. That is how dead ends leak.

Functions
  • _can_reach(n_states, arc_u, arc_v, goals)Predecessor matrix in CSR, then BFS backwards from the goal states.
  • q = (1 − absorb[au]) / outdeg[au]Quv on live → live arcs only.
  • One-sided data (ground)If only sources are significant, the measured, unchanged metabolites absorb (a = 1). If only targets are, walkers start evenly from them.
Packages
  • scipy.sparse.csr_matrixPredecessor lists for the reverse search.
  • collections.dequeThe BFS queue.
  • numpynp.isin / np.flatnonzero for target states, np.bincount for out-degrees.
5c

Factor once, get reach probabilities

splu(I − Q) · lu.solve(absorb)

Builds Q on the live states and LU-factorises I − Q once. Solving against the absorption vector gives h(u), the probability that a walk from state u ends at a target. h(s) for a source is its reach probability. Sources with h(s) ≈ 0 are excluded ("no directed path to a target"). The rest are weighted ws ∝ φs h(s), their share of all released walkers that reach a target.

Calls
  • sp.csc_matrix((q, (pos[au], pos[av])))Q, indexed by live-state position.
  • splu((I − Q).tocsc())The single factorisation, about 0.3 s on Human-GEM. Reused in 5d.
  • walk_success_fractionΣ φs h(s) / Σ φs: the share of released walkers that reach a target, reported in summary.json.
Packages
  • scipy.sparse.linalg.spluThe core numerical step, as in current flow but on a different matrix.
  • scipy.sparsecsc_matrix, identity.
5d

Expected traffic of successful walks

lu.solve(E, trans="T") · chunks of 128 sources

For a block of sources, the transposed solve gives ns, the expected number of visits to each state by walks released at s. Multiplying by Quv h(v) / h(s) keeps only the part of that traffic belonging to walks that end at a target. This is the Doob h-transform: per source, the conditioned walk is exactly one unit of flow from s to the targets. The same solve gives the share of s's successful walkers absorbed at each target, which decides the reached (s, t) pairs.

Calls
  • N[live_idx] = lu.solve(E, trans="T")Expected visits, one column per source in the block.
  • C = N[au] * (q * h[av])[:, None] / hsConditioned traffic on every arc.
  • absorbed = G @ N / hsShare absorbed at each target. A pair with no share goes to excluded as "no walk reaches this target".
Packages
  • SuperLU.solveReuses the factor from 5c; no new factorisation.
  • numpyDense blocks of 128 columns; broadcasting for the conditioning.
5e

Fold traffic back onto the graph

M @ C · |B|ᵀ · FlowResult(…)

Arc traffic is summed onto the original metabolite–reaction edges as signed net flow (+ towards the reaction, − away), so traffic that runs both ways through an edge cancels. A node's throughput is half the summed |net flow| on its edges, as in current flow. Walkers that stop at a target are subtracted there, so a target scores only what it relays onwards. A source's own walkers are not counted at that source. Per-source throughputs are then combined.

Results (FlowResult fields)
  • conductivity = accumulatedΣs ws Ts: weighted mean throughput (weights sum to 1).
  • bottleneckLargest throughput for any single source.
  • bottleneck_fracWeighted share of sources for which throughput ≥ τ (--bottleneck-tau).
  • edge_current · edge_max_currentWeighted mean and maximum |net flow| per edge; feed the Cytoscape subnetwork.
  • net_forwardNet flow on each reaction's substrate edges: > 0 used forward, < 0 used backward. NaN for metabolites.
  • conductivity_loo · bottleneck_looNaN: leave-one-out is not defined for the walk.
  • walk_infowalk_kappa, walk_one_sided, walk_success_fraction, walk_sources_unreached, walk_states, walk_live_states, walk_arcs.
Packages
  • scipy.sparse.csr_matrixM (arc → signed edge), |B|ᵀ (node × edge), S_fwd (substrate edges per reaction), G (absorption per target).
  • numpynp.maximum for bottlenecks; matrix–vector products for the weighted sums.
  • dataclassesFlowResult, imported from flow.py.
6

Score and rank: shared, one extra column

metaboenrich/scoring.py

Exactly as in pipeline.html step 6: final score = mean percentile rank of conductivity and bottleneck; genes take their best reaction; pathways by hypergeometric test on the top 100 reactions. The only code change is in node_table: if flow.net_forward is set, it adds a net_forward column, which carries through to reactions.tsv. Raw scoring only.

NoteIn source_target_metabolites.tsv, conductivity for a source is its reach probability; for a target, the share of successful walkers it absorbs.
7

Write outputs: shared, a few extra fields

metaboenrich/__main__.py · metaboenrich/cytoscape.py

Same files as the default run (pipeline.html step 7). Differences:

  • summary.json gains every walk_info field, and pair_weight reads "|log2FC| start weights (walk)".
  • excluded_pairs.tsv uses the walk's reasons ("no directed path to a target", "no walk reaches this target") and writes any where a row covers every target or source.
  • current_subnetwork.graphml keeps edges with max walker traffic ≥ --cytoscape-min-current (0.1).
  • The console line reports pairs reached, the share of walkers that reach a target, and how many sources reach none.
